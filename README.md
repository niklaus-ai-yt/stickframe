<h1 align="center">Stickframe</h1>

<p align="center"><b>Turn a voiceover into an animated stick-figure video, directed by any AI chatbot or the Claude app.</b><br>
Free, open source and runs on your own computer.</p>

---

Stickframe is a small studio app for making narrated, animated stick-figure videos for YouTube, Shorts, TikTok and Reels. An AI can write the script and plan every shot: paste prompts into any chatbot for free, or connect the Claude app and let it run the whole thing. Stickframe animates it, adds generated music and sound effects, and exports an MP4.

Every frame is drawn by code, so characters stay consistent, text stays sharp, and nothing is generated by image or video AI.

## What it does

1. **Script (optional).** Pick a niche, get 10 video ideas, approve a story breakdown (rules, fact bank, characters, sections), and get a narration script you can edit.
2. **Voice.** Drop in your voiceover from any text-to-speech tool (or your own recording). Stickframe times every word with speech recognition that runs on your machine. You can also import SRT/VTT subtitles, time a script with no audio, or make a quick draft voice with your computer's built-in voice.
3. **Storyboard.** The AI directs the video: locations, characters, poses and expressions on the right words, camera moves, close-ups, on-screen numbers and charts, effects, transitions, sound effects and music moods. You can change any shot in plain English ("make it a close-up of her shocked face and add rain") or edit its JSON.
4. **Preview & Export.** Watch an instant live preview, switch between five looks, then render 720p, 1080p, 1440p or 4K in 16:9 or 9:16, with optional word-by-word captions.

### Five looks

| Ember | Moonlight | Sketchbook | Chalkboard | Candy Pop |
|---|---|---|---|---|
| Warm cinematic evening light, ink figures with a glowing edge | Cool blue nights, silver edges | Hand-drawn ink on warm paper | Chalk lines on a green board | Bright flat colours, sticker-outlined figures |

### The animation kit

- **Characters:** expressive stick figures with 50+ poses (walk, run, point, panic, sit, fall, dance...), 25 facial expressions, blinking, talking mouths, speech bubbles, held props and 20+ wardrobe items. Each character has its own signature colour.
- **28 locations:** bedroom, office, café, classroom, hospital, lab, street, city, rooftop, park, forest, beach, lake, mountain, desert, stadium, road, space, underwater, stage, blueprint and more, each with day, sunset, night, indoor, cool, dark and abstract lighting.
- **90+ props**, plus graphics: titles, counters, timers, bar and line charts, meters, checklists, labels, badges, stamps, VS cards, questions and call-to-action pills.
- **Effects:** time-freeze, speed lines, zoom bursts, spotlight, heartbeat, glitch, lightning, fog, god rays, rain, snow, confetti, sparkles and more.
- **Audio:** 28 synthesized sound effects and generated background music in 8 moods, ducked under your voice and loudness-normalized for YouTube (−14 LUFS). You can also use your own music file and your own [sound library](#sound-library).

## Install

You need:

- **Node.js 20 or newer:** <https://nodejs.org>
- **ffmpeg:**
  - Windows: `winget install ffmpeg`
  - macOS: `brew install ffmpeg`
  - Linux: `sudo apt install ffmpeg`

Then download this repository (the green **Code** button, then **Download ZIP**, or `git clone` it) and in its folder run:

```bash
npm install
npm start
```

Stickframe opens at <http://localhost:4870>. On Windows you can also double-click `start-windows.bat`, and on macOS or Linux run `./start-mac-linux.sh`.

The first transcription downloads a speech model (about 290 MB, no account needed) into the Stickframe data folder. `node_modules` takes about 535 MB.

## Two ways to make a video

### Method 1: copy and paste (free)

This is the default. No account with Stickframe and no API key. Stickframe shows you each prompt, you paste it into any AI chatbot, and you paste the reply back.

Videos over 75 seconds go one part at a time, about a minute each, because a free chatbot may cut a long reply short. The window shows "Part 2 of 5". Stickframe carries the cast, music and locations into each prompt, merges the parts into one storyboard and saves your progress after every reply. If a reply is cut short or broken, it says so and you retry just that part.

Free voices, both with no account:

- **Your computer's built-in voice:** `node bin/sf.js say <id>`, or "draft voice" in the app. Nothing to install, but it sounds robotic.
- **Kokoro, a local AI voice:** `cd tools/free-voice`, `npm install`, then `node say.mjs script.txt voice.wav`. Downloads about 500 MB in total, including the 90 MB model. Upload the WAV with `node bin/sf.js voice <id> voice.wav`.

### Method 2: the Claude app runs it (MCP)

Needs the [Claude desktop app](https://claude.com/download) and a Claude plan (a paid plan works best for whole videos). There is no API key and no pay-per-use cost: Claude uses your plan.

1. In Stickframe, open **Settings**, choose **Claude app (MCP)** and click **Download the Claude extension**.
2. Double-click `stickframe.mcpb`. The Claude app opens and asks to install Stickframe. Click **Install**.
3. In Claude, ask for a video, for example: *"Make a one-minute What If video with Stickframe about the internet shutting down for a week."*

Claude gets Stickframe's tools over MCP (`bin/stickframe-mcp.js`): it writes the ideas, story and script, waits for your voiceover, times it, directs every shot, changes shots when you ask, and renders the MP4. It answers the same prompts the copy and paste mode shows, so every project stays a normal Stickframe project you can open and edit by hand. The extension is made on your computer with this folder's location written in, so download it again if you move the folder.

Other MCP clients can run the server directly: `node bin/stickframe-mcp.js` (stdio), with `STICKFRAME_PORT` and `STICKFRAME_HOME` if you changed them.

If you use Claude Code, the skill in `.claude/skills/stickframe` does the same job with the command-line tool below: open Claude Code in this folder and type `/stickframe what if every door opened somewhere random`.

## Command line

`node bin/sf.js help` lists everything. It talks to the local server and starts it if needed. A complete video:

```bash
node bin/sf.js new "My video" --resolution 1080p
node bin/sf.js voice my-video voiceover.mp3
node bin/sf.js transcribe my-video
node bin/sf.js prompt my-video --out prompt.txt
node bin/sf.js storyboard my-video reply.txt
node bin/sf.js render my-video --out my-video.mp4
```

Over 75 seconds, the storyboard goes in parts. Each `storyboard` command tells you what to run next, and later prompts depend on earlier replies, so do them in order:

```bash
node bin/sf.js prompt my-video --part 1 --out prompt-1.txt
node bin/sf.js storyboard my-video reply-1.txt --part 1
node bin/sf.js prompt my-video --part 2 --out prompt-2.txt
node bin/sf.js storyboard my-video reply-2.txt --part 2
```

`node bin/sf.js parts my-video` shows how far you have got. To send one prompt for the whole video instead, add `--whole` to both commands.

## Where things are saved

Everything lives in `~/Stickframe` (on Windows, `C:\Users\<you>\Stickframe`):

```
Stickframe/
  settings.json        your settings
  models/              downloaded speech models
  projects/<video>/    project.json, your voiceover, preview audio, out/*.mp4
```

Set `STICKFRAME_HOME` to use a different folder, or `STICKFRAME_PORT` for a different port.

## Speed

Rendering runs on every CPU core. On a modern desktop, 1080p renders far faster than real time: a 30-second test video finished in about 8 seconds on 8 cores. 4K takes roughly 4× longer than 1080p.

## Tips for great results

- **Write for pictures.** Concrete lines ("your coffee hangs in the air") make better shots than abstract ones.
- **Use the director notes** on the Voice step: "the hero is a kid with a red cap", "lots of numbers on screen", "keep it spooky".
- **Fix shots in plain English** rather than re-directing the whole video.
- **Try every look.** It's instant, so pick the one that suits the story.

## How it works

```
voiceover ─► local speech recognition (word timings)
                   │
script / notes ─► AI ─► storyboard JSON (shots, actors, props, graphics, fx, sfx, music)
                                   │
              validator (repairs unknown names, keeps timing contiguous)
                                   │
            engine/ (shared by browser preview and export renderer)
                                   │
        worker threads draw frames ─► ffmpeg (H.264) + mixed audio ─► MP4
```

- `engine/`: the animation engine (pure ES modules: rig, poses, faces, sets, props, overlays, effects, looks). The same code draws the in-browser preview and the exported frames.
- `server/`: the local server (projects, transcription, AI connection, audio synthesis and mixing, parallel rendering).
- `public/`: the studio UI (no build step).
- `tools/`: developer helpers. `npm run check` runs a self-test. `node tools/gallery.mjs poses out.png` renders a sheet of every pose; `sets`, `moods` and `wear` work too.

### Storyboard format

The AI writes JSON that only uses names from the engine catalog (`engine/catalog.js`). For example:

```json
{
  "id": "s4", "start": 8.8, "end": 11.0,
  "set": "livingroom", "light": "indoor",
  "camera": { "shot": "face", "on": "you", "move": "push", "shake": 0.3 },
  "actors": [{ "id": "you", "x": 0.5, "pose": "panic", "mood": "shocked", "face": "front" }],
  "text": [{ "type": "counter", "from": 0, "to": 20, "word": "20", "label": "blinks a minute" }],
  "fx": ["heartbeat", { "type": "freeze", "word": "stops", "hero": "you" }],
  "sfx": [{ "sound": "heartbeat", "at": 0.2 }]
}
```

Events can be timed with `"at"` (seconds into the shot) or `"word"` (fires when that word is spoken). See `examples/pause-button.json` for a complete storyboard.

### Sound library

The built-in sound effects are synthesized, but you can also use your own recorded samples. Put them in a folder with a `library.json`:

```json
{
  "version": 1,
  "sounds": {
    "whoosh_soft": { "file": "whooshes/soft.wav", "gain_db": -3, "description": "gentle air swish", "license": "CC0", "source": "https://..." },
    "D1": { "file": "C:/sounds/door-slam.wav", "gain_db": 0, "description": "heavy door slam" }
  }
}
```

`file` can be relative to the folder or absolute, in any format ffmpeg reads. Then point Stickframe at it: set the project field `sfxLibrary` (the folder or the `library.json` path, for example via `PATCH /api/projects/<id>`), or set `STICKFRAME_SFX_LIBRARY` for every project.

With a library active, the AI sees its IDs and descriptions when directing, and storyboard sfx can use them like any other sound: `{ "sound": "whoosh_soft", "word": "gone", "gain": -2, "pan": -0.5 }`. `gain` (dB) adds to the library's `gain_db`, `pan` runs from -1 (left) to 1 (right), and samples dip slightly under the narration unless you add `"duck": false`. Samples are peak-normalized like the built-in sounds, so `gain_db` is a trim relative to them. Any name that isn't in the library falls back to the synthesized sounds. Only use samples whose licences allow your use, and keep the `license` and `source` fields so you can credit them.
